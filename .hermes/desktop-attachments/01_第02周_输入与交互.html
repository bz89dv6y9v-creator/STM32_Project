第 2 周 · 输入与交互（T2）

第 2 周 · 输入与交互（T2）

这周做什么：接一个按键，按下它切换 LED 的模式，再把"现在是什么模式"从串口打出来——顺便亲手抓住"按一次、跳三格"的抖动。 学完你能：给一个按键引脚挑对接法（上拉还是下拉）、一眼看出"连跳"就是抖动、用自己的办法把它消掉，并让板子把当前状态说给你听。 要花多久：2–4 小时，可以分两个晚上。这周的难点不是写代码，是"松开手的时候到底读到 0 还是 1"和"去抖时间取多少"——这两件都得你自己动手量出来。 需要什么：第 1 周那块 STM32C8T6 最小系统板 + 兼容版 ST-Link 下载器 + USB 线 + 电脑（软件都已装好，这周不用再装任何东西）；面包板 + 杜邦线；轻触按键 ×1、10kΩ 电阻 ×1、LED ×1、限流电阻 ×1——这几样由实验室统一买，开课前找学长领；有万用表就借一块（量引脚电平用，实验室共享）。 配套：每周作业评分表、C 语言（一）把数摆对：类型、常量与运算——这两份都在本文件夹里，跟这份文件一起发给你。听不懂任务卡里的语法（uint8_t、if、sprintf、&、volatile 这些东西到底是什么）就先翻这一讲，它是拿第 1、2 周任务卡里的代码逐行拆的。想学得更深的（中断、参考手册那一路），整套学习材料里有对应的讲义，需要时找学长要。 一句话：按键"能用"不算过关，能说清"松开的时候读到几""按一次为什么只跳一格"，才算过关。

一、这周你要做到什么

验收标准（五条，缺一条就要补）：

  1. LED 有至少三种一眼就能分出来的模式（比如常亮 / 慢闪 / 快闪），按一下键换一种，转一圈回到第一种。
  2. 连按 20 次，模式只跳 20 格——不是"按一下跳三下"。也就是说：去抖真的做了，而且你能说出这个参数是怎么试出来的。
  3. 串口能把当前模式打出来，而且打得让人看得懂（MODE=2 比光一个 2 有用一百倍）。
  4. 你能当场说清三件事：我的按键是上拉还是下拉；按下去读到 0 还是 1；去抖窗口取了多少、凭什么取这个数。
  5. 板子会自己说话：你交的 log.h / log.c 能跑起来——串口上每一行日志带时间戳、等级和模块标签（形如 [12345][I][M] MODE=2）；把等级从 DEBUG 调到 WARN，DEBUG/INFO 那些行当场消失（现场演示给学长看）；日志满了不会把主循环卡住（log_dropped() 非 0 要在记录里写出来、并说清你是怎么发现它满的）。

二、先看三件真会发生的事

先不要管名词。这三件事你这周大概率会全部遇上，遇上了不要慌，它们都是正常的。

1. 你只按了一下，程序却以为你按了三下。 不是你手抖，也不是板子坏了：轻触按键里面是弹片，合上的那一瞬间会来回弹几下，几十微秒到几毫秒里，引脚上的电平会抖成一串高低。这就是这周的题目本身——遇上它说明你已经摸到边了，接下来要做的不是"按轻一点"，而是把它从程序里消掉。

2. 灯的模式跳得好好的，串口打出来却是一串乱码。 十有八九是两边波特率不一致，不是线坏了、也不是模块坏了。顺序永远是：先回去看时钟树 → 再对两边的波特率 → 最后才怀疑硬件。

3. 松开手的时候引脚读到的是 0 还是 1，跟你以为的正好相反。 引脚读到什么由电路决定，不由代码决定——取决于按键另一端接的是 GND 还是 3.3V，以及你在 CubeMX 里把引脚配成了上拉还是下拉。这三样凑错一个，现象就整个反过来。不要背结论，用万用表量一次。

还有一件小事会在这周埋下伏笔：串口一旦通了，你就多了一只"眼睛"。 从这周开始，调试不用再靠猜——后面的采集、显示、循迹阈值标定，全靠这条打印通道把板子内部的状态说给你听。早点把它用顺手。

3.1 第一步：把按键接到板子上（两种接法，挑一种）

先看图。同一件事有两种接法，两种都对，但"没按的时候读到什么"刚好相反：

比什么 接法 A：上拉 接法 B：下拉
按键的一端接 GND 3.3V
引脚在 CubeMX 里配成 GPIO_Input + Pull-up（上拉） GPIO_Input + Pull-down（下拉）
没按的时候读到 1 0
按下的时候读到 0 1
它为什么是这样 电阻先把引脚拉到高电平，按下时被按键短到地 电阻先把引脚拉到低电平，按下时被按键抬到 3.3V

三条要记住的：

  1. 不要配成"浮空"（No pull）。 引脚什么都不接的时候电平是飘的，读到什么全看手摸不摸板子——这是新手最常见的"我的按键时好时坏"。
  2. 先猜、后验。 接线之前先在纸上写一句"我预期松开读到 、按下读到 "，接好线、上电、打印出来对一遍。对不上不要往下走，先用万用表量引脚对地的电压：没按时≈3.3V（上拉）或≈0V（下拉），按下时反过来。以量到的为准，不以教程为准。
  3. 用哪两个引脚，看你板子上的丝印和卖家给的原理图。 第三方最小系统板没有统一的官方文档，别人的教程用的是别人的板子。引脚号自己确认。

配好之后在 CubeMX 里：把那两个引脚分别设成 GPIO_Input（按键）和 GPIO_Output（灯，第 1 周已经配好），Pull-up/Pull-down 按你选的接法选，重新生成代码。

3.2 第二步：故意不去抖，先亲眼看一次抖动

这一步是故意做错一次——本周末你要在同一段录像里拿它做对比。

在主循环里做一件很简单的事：每一圈读一次按键引脚，发现电平"变了"就让计数加一，然后每 500 毫秒通过串口把这个计数打出来。

/* 只做一件事：数"变了多少次" —— 故意不做去抖 */
uint32_t count = 0;
GPIO_PinState last = HAL_GPIO_ReadPin(KEY_GPIO_Port, KEY_Pin);

while (1)
{
    GPIO_PinState now = HAL_GPIO_ReadPin(KEY_GPIO_Port, KEY_Pin);
    if (now != last)          /* 只要电平变了就记一笔 */
    {
        count++;
        last = now;
    }
    /* 每 500ms 把 count 打出来（打印怎么写见 3.4） */
}

然后连按 20 次，盯着打印看。 你会看到计数远远超过 20——按十下能数出七八十。这就是抖动，它不是一个说法，是可以拍下来的数字。

别跳过这一步。 没见过抖动的人，去抖就只是从别人那里抄了一个数；见过的人，才知道自己在消掉什么。

3.3 第三步：让按键切换 LED 模式（先不管抖动）

先把功能做出来，抖动最后收拾。思路只有一句：用一个变量记住"现在是第几种模式"，按一下就让它往后挪一格。

uint8_t mode = 0;            /* 0 / 1 / 2 三种模式 */
#define MODE_COUNT 3

/* 在检测到"一次有效按键"的地方： */
mode = (mode + 1) % MODE_COUNT;      /* 0 → 1 → 2 → 0 … */

三种模式自己定，但要一眼分得出来。比如：0 = 常亮、1 = 慢闪、2 = 快闪。切换的逻辑只改 while (1) 里那几行，CubeMX 那边一个字都不用动。

同一件事，两套库的写法对照（作业一律用 HAL 那一列）：

/* ---- 标准库（江协科技那套教程的写法）---- */
if (GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_0) == Bit_RESET) { /* 按下 */ }

/* ---- HAL 库（我们这门课，工程由 CubeMX 生成）---- */
if (HAL_GPIO_ReadPin(KEY_GPIO_Port, KEY_Pin) == GPIO_PIN_RESET) { /* 按下 */ }
比什么 标准库（江协那套） HAL 库（我们这门课）
读一个引脚 GPIO_ReadInputDataBit(GPIOA, GPIO_Pin_0) HAL_GPIO_ReadPin(KEY_GPIO_Port, KEY_Pin)
读到"低电平"怎么比 == Bit_RESET（0） == GPIO_PIN_RESET（0）
引脚怎么配成输入 手写 GPIO_InitTypeDef（GPIO_Mode_IPU / _IPD） CubeMX 里选 Pull-up / Pull-down，代码自动生成
宏名大小写 GPIO_Pin_0 GPIO_PIN_0

提醒：KEY_GPIO_Port、KEY_Pin 这种名字是 CubeMX 按你给的用户标签生成的宏。用你工程里自动生成的那个名字，别抄别人的——抄了不是编译报错，就是控制到了别的引脚。

一个容易踩的坑：如果一种模式是"慢闪"，你就不能用 HAL_Delay(500) 把主循环堵在那里——那样按键读不到、串口也打不出来。闪烁的节奏要跟读按键并行，办法在 3.5 节（时间戳法）。这不是绕不过去的难题，是这周最值得学会的一件事。

3.4 第四步：串口打印——给板子装上"眼睛"

在 CubeMX 里打开 USART1（模式选 Asynchronous），波特率先按 115200 配，生成代码。两边要设成同一个数——板子这边一个数、电脑那边一个数，不一样就是乱码。

发一串字符，最直接的写法是：

char msg[32];
int len = sprintf(msg, "MODE=%d\r\n", mode);
HAL_UART_Transmit(&huart1, (uint8_t *)msg, len, 100);

电脑这一头不用另装工具：STM32CubeIDE 自带串口终端。打开终端视图（Window ▸ Show View ▸ Terminal），新建一个终端时把连接类型选成 串口 / Serial，挑出板子那个 COM 口，参数照 CubeMX 里配的那一套填——波特率 115200、数据位 8、校验 None、停止位 1，就能看到打印了。

这几个参数必须和板子那边一模一样，少对一个就是乱码。 现实里最常见的栽法不是波特率错，而是波特率对了、数据位或校验位没对上——一样满屏乱码。所以乱码先逐项参数对一遍，再谈换线。菜单名字各版本略有差别（有的版本要去 Window ▸ Show View ▸ Other… 里找 Terminal）——实在找不到就先问学长，或者临时用任意一个串口工具，参数对上就行，工具不是重点。

串口三条纪律（背下来，能省你很多时间）：

  1. 两边参数必须一致（波特率 / 数据位 / 校验位 / 停止位）。不一致就是乱码。乱码的第一反应是把两边参数逐项对一遍，不是换线。 而波特率是从时钟算出来的——所以真正的第一反应其实是回去看时钟树（第 1 周那三格数就是为这件事准备的）。
  2. 打印不要放在高频中断里。 发一次字符串要占几百微秒到几毫秒，塞进很快的中断里，别的事全被堵住。
  3. 打印内容要写清含义。 MODE=2 比光一个 2 有用一百倍；能带上名字更好（MODE=2 (慢闪)）。打印是给你自己看的，别让三天后的你猜。

故意做一次错事：把电脑这头的波特率改成 9600，看屏幕上那一串乱码，再改回 115200；再把数据位从 8 改成 7 试一次——照样是乱码。这一下之后，"乱码先把两边参数逐项对一遍"就是你自己说的话了。

3.5 第五步：把抖动消掉（这周的重点）

去抖的思路只有一句：别相信"电平一变就算一次"，要相信"电平稳定地维持了一小段时间，才算一次"。

两种做法都行，先看差别：

比什么 延时法（最省事） 状态机 / 时间戳法（这周建议用这个）
怎么做 发现电平变了 → 等 20ms → 再读一次，还是新电平才算数 记下"电平是上一次什么时候变的"，主循环里每圈比一比这个新电平已经稳定多久，超过阈值才算一次有效按键
代码量 三行 多一个变量、十几行
代价 等待那 20ms 里，主循环什么都干不了——灯卡一下、串口停一下。这就是第 1 周 HAL_Delay 的代价，你这次能亲眼看到 一行都不等，灯该闪照闪、串口该打照打
什么时候够用 按键是你唯一要做的事 只要还有灯在闪、还有别的活在干——也就是从这周开始的所有情况

时间戳法的骨架（不是抄，是看结构）：

uint32_t last_change_ms = 0;      /* 电平上一次变化发生在什么时候 */
GPIO_PinState stable = ..., last = ...;

while (1)
{
    GPIO_PinState now = HAL_GPIO_ReadPin(KEY_GPIO_Port, KEY_Pin);
    if (now != last) { last = now; last_change_ms = HAL_GetTick(); }   /* 只记账，不判定 */
    if ((now != stable) && (HAL_GetTick() - last_change_ms > 去抖毫秒数))
    {
        stable = now;                 /* 稳定够了，这才算"真的变了" */
        /* 在这里做一次有效按键的处理：切模式 + 打印 */
    }
    /* 灯的闪烁、别的活儿，都放在这里并行做（比较 HAL_GetTick() 的差值，不要用 HAL_Delay 死等） */
}

参数自己测，不要抄一个数。 我给你的判断标准是现象，不是数字：连按 20 次，模式只跳 20 格。 去抖窗口取多少，以你手上这颗开关的实测为准——太小了还跳，太大了按快一点就丢键。测的时候中间多试几个值（比如 5ms / 20ms / 50ms 各按 20 次），把结果记下来。

把"我试了哪几个值、最后取了哪个、为什么"写进一页记录——这一句就是加分项，也是抽查最可能追问的那一句。

3.6 第六步：用调试器把程序停住看一眼（本周新技能）

串口打印是第一只眼睛，但它只能告诉你你事先想到要看的东西，而且打出来的是"某一刻的快照"。调试器是第二只眼睛：它能把程序按在原地，让你看真实的变量值。 从这周起，你干活的循环就固定下来了——

改代码 → 编译 → 下载 → 调试（停住看）→ 串口打印 + 录像（看长时间的样子）→ Git 提交。

怎么开始：点 CubeIDE 工具栏上那只小虫子（或者右键工程选 Debug As ▸ STM32 C/C++ Application）。第一次会让你选探头，选 ST-LINK。程序跑起来后会先停在 main 开头——这时候板子是被你按住的，按 F8 让它继续跑。

三个动作，这周各做一遍：

动作 怎么做 用来回答什么问题
打断点 在代码左边的行号上双击，出现一个小圆点 "程序走到这一行的时候，count 到底是几？"
单步 F5 进函数 / F6 跨过这一行 / F7 从函数里返回 / F8 跑到下一个断点 "它到底是怎么判断的？一行一行看"
看变量 Variables 视图看当前函数里的变量；想看全局的或自己拼的表达式，选中变量右键 Add Watch Expression，或者用 Live Expressions 把 mode、时间戳一直挂在屏幕上 "这些数现在到底是多少？"

把这三种单步拆开看，各用在哪（键盘上就是 F5 / F6 / F7 这三个键）：

单步 键 什么时候用它
Step Into（进函数） F5 你想知道"这个函数里面到底干了什么"——比如走进 HAL_GPIO_ReadPin，看它到底读的是哪个寄存器
Step Over（跨过这一行） F6 这一行你信得过、不想进去——比如 HAL_GetTick()、sprintf()，一按就跳过去
Step Return（从函数里返回） F7 进错了、或者看够了，一下退回调用它的那一行，不用一步步走完

条件断点：只在"条件成立的那一次"停住。 普通断点是"每到这里都停"——主循环里那一行一秒能过几千次，你根本按不过来。做法：在已经打断的那个断点上右键 → Breakpoint Properties，勾上 Conditional，把条件写成表达式（比如 count > 20、now != last）。这一条比什么都好用：它可以和串口打印互相验证——串口说"这里走了 500 次"，条件断点就能在第 500 次把你按在那儿，让你看清当时的几个变量。

调用栈窗口（Call Stack）：程序停住的时候，它告诉你"我是从哪儿一路走到这一行的"。中断和回调里最有用：断点打在 HAL_GPIO_EXTI_Callback 里，你能顺着栈看到它是被中断服务函数、再被硬件事件一层层调进来的。"这一行到底是谁调的"，看栈，不要猜。

Live Expressions 是"一直挂在屏幕上"的那几个量：Variables 只显示当前函数里的变量，Watch 要你自己一条条加；Live Expressions 把 mode、last_change_ms、log_dropped() 这类你盯着的量一直摆在屏幕上，单步的时候它们实时地变——比每停一次再加一次 Watch 省事得多。

复位和暂停是两回事：F8 是"继续跑"，停下来看是暂停；工具栏上那个红色方块是复位——一按，程序从头开始，你刚才看到的变量全部清零。想看中间状态用暂停，想看从头来的过程才用复位。

把它用在抖动上，你会看到比串口更狠的证据：

  • 断点打在"检测到电平变化就 count++"那一行，运行，然后连按一次键——程序会在这一下里停住好几次。停了几次，就是这一下被当成了几次按键。串口要等到下一行打印才看得出来，这里一按就见分晓。
  • 去抖做完（3.5 节）之后，同一个断点，一次按键只停一次。
  • 用 F6 单步走一遍时间戳法的判断，盯着 now - last 那个差值：抖动的时候它根本涨不到阈值——你就明白那个参数为什么能挡住抖动。

三个必须知道的注意点：

  1. 停在断点上，程序就是冻结的。 主循环不转了，灯不闪、串口也不打——但外设和硬件还在动。断点会让程序停住，所以不能用来看时序——"这灯到底闪多快""主循环一圈多久"，一律靠串口打印或示波器，不要靠断点。
  2. 改完代码要重新编译下载；拔插过 ST-Link 或者连接掉线，就重新点一次调试。断点会留在代码里，不用重打。
  3. volatile 变量在变量窗里才不会被优化掉。 主循环和中断共用的变量（key_flag、日志库那个环形缓冲的头尾指针）不加 volatile，编译器可能把"每圈读它一次"优化成"用寄存器里的旧值"——这时候你在变量窗口里看到的就不是真正的内存值，单步下去程序的行为和你看到的对不上。看不到中断写进去的值时，先回头检查声明（第 1 周提过一次，这周真的会碰上）。

记录里写一条：这周你在断点里看到的数，和串口打印告诉你的，哪里不一样；如果一样，就写清你用哪一种验证了什么。

这周不用学：寄存器视图、反汇编、SWO / ITM 那些"高级货"（我们这块 F103 的板子也不支持用 SWO 打印，别在这上面浪费时间）。会停、会走、会看三个变量，就够用了。

3.7 第七步：让板子自己说话——一个够用的日志库（本周新技能）

3.4 你学会了"发一行字符串"，3.6 你学会了"把程序按停看一眼"。可真干起活来你会发现：打印这件事本身需要有人管——打什么、打多少、哪个等级该出现、哪个等级该闭嘴、打不过来的时候丢哪一条。这一节只干一件事：自己写一个只属于你这块板子的小日志库。

这是这周新增的那件交付物（见 §一 交付表第 4 行），也是下周 T3 直接接着用的东西：ADC 读到的三组原始数据、蓝牙发出去的那串数，都得先经过它才成形。

3.7.1 为什么要"分级"：四级，两种开关

日志不是"想打就打"，是先定等级、再决定谁能出来。四个等级，从"最该看见"排到"最啰嗦"：

等级 什么时候用 例子
LOG_ERROR 只有坏了才打 ASSERT 失败、外设初始化失败
LOG_WARN 可疑但还能跑 串口收到不认识的东西、去抖窗口取得明显偏大
LOG_INFO 正常的关键节点 开机、模式切换
LOG_DEBUG 排查时才要的细节 每一圈的按键电平、时间戳差值

两级过滤，缺一不可：

  • 编译期开关：在 log.h 里把 LOG_COMPILE_LEVEL 定义成 LOG_WARN，比它更啰嗦的语句在编译的时候就被扔掉——不占 Flash、也不占运行时间。这是"发布版一条调试日志都不带"的做法。
  • 运行期开关：一个变量（log_set_level() 改的那个）。板子已经在跑了、现象就在眼前，你不可能停下来重新编译一遍——现场就靠它。

为什么非要能"一声令下全都不打"：因为日志本身会改变时序。你要量"主循环一圈多久""波形对不对"的时候，串口打印就是干扰源。量时序之前先把等级关到 WARN，是这周要养成的条件反射。

同一段代码，两种等级下的串口完全不是一个样子。DEBUG 全开时每一圈都在刷：

[1024][D][K] key level=1
[1025][D][K] stable for 3ms
[1026][I][M] MODE=2
[1027][D][K] key level=1

把等级调到 WARN，同一段代码只剩这一行：

[1500][W][K] debounce 50ms too large?

左边那种串口是没法看的；你要的是右边那种。

3.7.2 接口先定死：log.h

接口由这张任务卡定死，实现由你自己写。 先把 log.h 照着敲出来（一个字都别改，改了后面对讲义里的参考实现对不上）：

/* log.h */
#ifndef LOG_H
#define LOG_H
#include <stdint.h>

typedef enum {
    LOG_ERROR = 0,   /* 只有坏了才打 */
    LOG_WARN  = 1,   /* 可疑但还能跑 */
    LOG_INFO  = 2,   /* 正常的关键节点（开机、模式切换） */
    LOG_DEBUG = 3    /* 排查时才要的细节，默认这一档最多 */
} log_level_t;

/* 编译期上限：比它更啰嗦的语句在编译时就被扔掉，不占 Flash 也不占时间 */
#ifndef LOG_COMPILE_LEVEL
#define LOG_COMPILE_LEVEL  LOG_DEBUG
#endif

void        log_init(void (*write)(const char *s, uint16_t n)); /* 注入"怎么发出去" */
void        log_set_level(log_level_t lv);                      /* 运行期也能改 */
log_level_t log_get_level(void);
uint32_t    log_sent(void);       /* 已经发出去的条数 */
uint32_t    log_dropped(void);    /* 因为缓冲满被丢掉的条数 */

void log_printf(log_level_t lv, char tag, const char *fmt, ...); /* 主循环/普通代码里用 */
void log_flush(void);                                           /* 主循环里反复调 */

#define LOG_E(tag, ...) log_printf(LOG_ERROR, tag, __VA_ARGS__)
#define LOG_W(tag, ...) log_printf(LOG_WARN,  tag, __VA_ARGS__)
#define LOG_I(tag, ...) log_printf(LOG_INFO,  tag, __VA_ARGS__)
#define LOG_D(tag, ...) log_printf(LOG_DEBUG, tag, __VA_ARGS__)

#endif

为什么是这几个函数、这四个宏：

  • log_init(log_uart_write)：日志库不认识串口。它只知道"有一个函数能把 n 个字节发出去"，这个函数由你在 main.c 里塞进去。这样日志库不用引 huart1；以后你想改成蓝牙、想改成先存内存，都不用动它。
  • log_printf(等级, 标签, 格式, ...)：只有一个出口，等级和标签都当参数传。标签是一个字符（'M' = 模式、'K' = 按键、'A' = 断言），一眼看出这行是谁打的。
  • log_flush()：真正的"发出去"发生在主循环里，不在你调 LOG_I 的那一瞬间。你调 LOG_I 时，日志只是躺进内存；log_flush() 才把它送出去。这个函数就是你的日志库不卡主循环的全部秘密。
  • 四个宏 LOG_E / LOG_W / LOG_I / LOG_D：让调用处短到一行写得完，顺手把等级也带进去。
  • log_sent() / log_dropped()：这两个数是你的证据——发了多少条、丢了多少条，抽查要问（见 §一 第 5 条）。

3.7.3 自己写实现：log.c

这一节只给骨架和注释要求，不给整份实现——整份参考实现在讲义《调试与日志库》里，你写完之后对着看。你要写出来的是下面这四步，抽查时会让你指出每一步在哪一行：

  1. 两级过滤：先比编译期上限（LOG_COMPILE_LEVEL，啰嗦的那几条编译完根本不存在），再比运行期等级（log_get_level()）。
  2. 格式化到栈上：用 vsnprintf 把这一行格式化成 [时间戳][等级][标签] 正文\r\n，放进一个栈上的小缓冲，96 字节封顶。为什么不能开大——vsnprintf 用的是调用者的栈，中断里用一个几百字节的大缓冲就是拿栈冒险。
  3. 关中断，拷进环形缓冲：环形缓冲是一个定长数组（512 字节，写死，不用 malloc）。往里面放的时候要关中断极短时间（拷进去就开），因为主循环和中断都可能来放。512 字节这个数是算得出来的：一行日志 60–90 字节，装得下 5–8 行。满了就丢新的那条并让 s_dropped++，然后原样返回——绝不等待、绝不覆盖旧数据（旧数据是你已经发生过的事，新数据还可能再来一次）。
  4. 主循环里 log_flush()：把缓冲里攒的这一批用一次非阻塞发送送出去（HAL_UART_Transmit_IT，或者自己查 TXE 标志一个字节一个字节发）。不要用带大超时的阻塞发送——那一等，主循环就卡在那儿了。

3.7.5 断言：ASSERT 只留给"绝不可能"

日志解决"程序说话"，断言解决"程序再也说不下去了"。ASSERT(条件) 的意思是：这个条件不成立，我这套逻辑的地基就塌了，没有继续跑的意义。

写在哪：函数开头检查"必须成立才能往下走"的前提——指针不是空的、中断必须已经开、缓冲区长度只能是 512。

失败时你要能看到现场：文件、行号、还有哪个条件没成立。参考写法（放在 log.c 里，或者单开一个 assert_port.h——你自己选一处，别两处都放）：

#define ASSERT(cond) do { if (!(cond)) { \
    LOG_E('A', "ASSERT %s:%d: %s", __FILE__, __LINE__, #cond); \
    log_flush(); for (volatile int i=0;i<200000;i++){} __disable_irq(); while (1) {} } } while (0)

失败时串口上会出现 [12345][E][A] ASSERT key.c:88: s_buf != 0 这样一行，然后停机（上面是死循环；也可以改成复位，但要留够时间把那行日志发出去）。编译期还能再断一次：_Static_assert(sizeof(int)==4, "int 不是 4 字节");——这种错在编译的时候就报出来，比跑到板子上才发现便宜得多。

为什么不能拿它当错误处理：断言失败是停机。用户长按了三秒、串口收到一个不认识的字节——这些都是可预期的事，应该用返回值或分支处理掉，不是把整个程序按死。可预期的问题走返回值，ASSERT 只留给"真的不可能发生"的地方。

3.7.6 四条铁律（抽查会问）

  1. 中断里只登记、不打印。 中断里可以调 log_printf（它格式化在栈上、拷进缓冲只关一下中断），但绝对不许在中断里直接发串口、不许 printf——发送要等硬件，那些函数又不保证可重入。写错这一句，板子看起来就像死机（见 §一「会坏」和 §四 排查表"主循环像卡住"那一行）。
  2. 格式化缓冲不超过 96 字节。 它开在栈上，开大了就是拿栈冒险——中断一进来，栈只会更紧。
  3. 缓冲满了要计数，不许覆盖旧条。 丢新的那条、让 s_dropped++：旧数据是你已经发生过的事，新数据还可能再来一次。
  4. 日志不能在主循环里阻塞。 log_flush() 用非阻塞发送，禁止带大超时的阻塞发送；发不出去也要能立刻返回。

3.9 一页记录怎么写

3.11 附：轮询还是中断？中断里能做什么、不能做什么

这周你用轮询就能达标（主循环每圈读一次引脚，就是 3.5 节那段写法）。但中断是后面所有任务的底座——定时器、串口的收数据、循迹的计数，全都要用它。提前认识它只有好处。

先看什么时候该用哪个：

比什么 轮询（主循环里一遍遍读） 中断（事件来了打断你）
什么时候发现按键 下一圈读到才发现，最坏要等一整圈 电平一变立刻响应
会不会漏掉事件 事情多了就会漏（主循环忙的时候顾不上） 不会漏
代码复杂度 最简单，好懂 多一套回调机制，容易踩坑
什么时候用它 同时只有一个输入、主循环很闲 要同时管灯、管打印、管按键，还要管定时

中断里的正确姿势，只有一条：中断只负责"记一笔"，真正的活留给主循环干。

/* 中断回调里，只翻一个标志位 */
volatile uint8_t key_flag = 0;

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (GPIO_Pin == KEY_Pin) { key_flag = 1; }
}

/* 主循环里再去抖、切模式、打印 */
while (1)
{
    if (key_flag) { key_flag = 0; /* 这里干活，可以慢慢来 */ }
}

三条禁忌（记住这三条，能避免一大类"程序莫名其妙卡死"）：

  1. 中断服务函数里不要用 HAL_Delay。 中断里死等，会把整个系统拖住。
  2. 不要在高频中断里做长串口打印。 同上，几毫秒就够毁掉实时性。
  3. 主循环和中断共用的变量要加 volatile。 不加，编译器可能把它优化成"只在寄存器里改过一次"，主循环永远看不到中断写进去的值。

同一件事，两套库的写法对照：

干什么 标准库（江协那套教程） HAL 库（本课程）
中断服务函数里写什么 直接判断、直接干活：EXTI_GetITStatus(EXTI_Line0) / EXTI_ClearITPendingBit(...) 调一次 HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_0)，真正的活写在回调 HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin) 里
中断入口在哪 自己写 EXTI0_IRQHandler(void) CubeMX 生成的 stm32f1xx_it.c 里已经写好了，你只填回调
宏名大小写 GPIO_Pin_0 GPIO_PIN_0

一个特别容易栽的小坑（第 1 周提过一次，这周真的会碰上）：同一个引脚，标准库写 GPIO_Pin_0、HAL 写 GPIO_PIN_0，只差一个字母的大小写，抄错了连编译都过不去，报错还是一串看不懂的红字。看到这种报错，先回头看看宏名。

这周不出意外的话，你就待在轮询这一列就够了。 上面这些不是作业，是让你下次见到中断代码时不至于发怵。

3.12 进阶任务与自由发挥（选做，但很值）

前面这些做完你就达标了。下面这些都不算必须——但做得出来说明你真的会了，而且"记住谁"往往就靠这一条：同一块板子、同一个要求，别人只做到"按键能用"，你多想了一个功能。

进阶任务（挑一个做，做几个都不嫌多）

  1. 区分长按和短按：按住超过 1 秒算"长按"（比如让灯快闪两下当提示），短按才是切模式。这一条逼你把"按键持续了多久"也算出来。
  2. 双击加速：两次按键间隔很短就算"连按两下"，让灯闪得更快一档。
  3. 把模式说成人话：串口不只打 MODE=2，打一整句——现在是：慢闪（0.5 秒一次）。想一想字符串怎么拼，为什么不能用 HAL_UART_Transmit 一个一个字节发（可以，但慢）。
  4. 给按键一个回声：按一下，板载灯立刻给你一次很短的回执闪（比如 50ms）——"我收到了"。用户按下去有没有反应，是"能用"和"好用"的分界。

自由发挥：你自己的按键玩法

想做几个模式就做几个模式——按键当开关、按一下切换"呼吸 / 常亮 / 全灭"、用灯把按键次数"读"出来、做一个只有你知道的隐藏组合……只要是你自己想出来的就行。

三条规矩：① 只用手上这块板子上的东西，不接电机、不接底盘、不接任何传感器模块；② 代码必须你自己写，AI 生成的一个字都不能出现在提交里；③ 在 记录.md 里单开一段「自由发挥」，写清你想做什么、怎么做的、最后做出来什么效果，录像里也讲一遍。

为什么要加这一条：招聘和比赛看的不是"你会不会读按键"，是"这东西是你想出来的、还是照着抄的"。多做一个别人没要求的功能，就是最便宜的证据。

记录.md 里长什么样（看格式，别抄内容）

  • 想做什么：三个模式切来切去，每次都要按好几下才回到想要的。我想让长按 1 秒直接跳到一个"设置模式"——灯快闪三下表示进来了，再短按可以直接挑模式。
  • 怎么做的：在时间戳法的基础上多记一个变量：按下的那一刻记时间，松开的那一刻再减一次。差值超过 1000ms 就算长按，走另一条分支。去抖的阈值一点没改，长按判断是加在它后面的。
